# 工作台首页总览增强设计

## 背景

当前项目已经具备 Git 仓库扫描、Web 服务探测、Save Point、进程/端口管理、系统指标和 AI 雷达等独立页面。首页 `OverviewView` 目前只承载 KPI、网络波形、延迟、抓包和 Socket，用户打开应用后仍需要在多个页面之间切换才能回答“哪些项目有改动、哪些服务正在运行、系统是否健康”。

## 目标

把已有能力编排成一个可操作的总控首页，不重复实现扫描器或服务探测器：

- 首屏优先展示项目与运行服务状态。
- 同时提供系统健康摘要和开发工具/AI 的快速入口。
- 保留现有实时网络、延迟、抓包和 Socket 视图，避免回归已有监控能力。
- 所有动作都复用现有 store API，失败通过既有 Toast 反馈。
- 新增文案同时进入中英文词典，组件不写硬编码用户文案。

## 方案

采用“总览编排层”方案，在 `OverviewView` 增加四个轻量面板：

1. **工作台头部与刷新动作**：显示整体标题、最近刷新动作，并并行刷新 Git 项目、Web 服务和机器信息；提供进入 Git 仓库、Web 产物、AI 雷达页面的入口。
2. **项目脉搏**：基于 `gitProjects` 计算仓库总数、未提交仓库数和领先/落后仓库数；按脏状态和最近提交排序展示最多 5 个项目。每个项目支持打开 VS Code、终端、Save Point，点击“查看全部”进入现有 Git Radar。
3. **运行服务**：基于 `webArtifacts` 展示健康/异常服务、端口、框架、响应时间和打开网页动作；异常服务复用现有释放端口动作；点击“查看全部”进入 Web Artifacts 页面。
4. **本机健康与快捷入口**：汇总 WebSocket 状态、CPU/内存、磁盘使用率、电池状态、已安装开发工具数量，并提供 AI Radar、环境探针、运维总控入口。

现有 `TrafficWaveform`、`LatencyMatrix`、`PacketSniffer`、`SocketInspector` 继续显示在下方，作为深度监控区。

## 数据流与错误处理

- 页面挂载时沿用 `App` 的预取；首页刷新按钮调用 `scanGitProjectsApi()`、`fetchWebArtifactsApi()`、`fetchMachineInfoApi()`，使用 `Promise.all` 并行执行。
- 空数据展示明确的空状态，不把“尚未加载”误报成“无项目/无服务”。
- Git/Web 服务动作复用 `openAppApi`、`openSnapshotDrawer`、`freeArtifactPortApi` 和 `window.open`，不新增后端接口。
- 刷新失败沿用 store 现有错误日志/Toast 机制；面板本身保持可用。

## 视觉与无障碍

- 复用现有 `hud-box`、`glass-card`、`Badge`、`Button` 和 Tabler 图标。
- 面板使用响应式网格，窄屏单列、宽屏多列。
- 每个操作按钮提供词典化 `aria-label`；状态使用文字和颜色双重表达。
- 不引入 Emoji 作为 UI 图标。

## 验收标准

- 首页首屏能看到项目、运行服务和系统健康摘要。
- 项目卡片可直接打开编辑器/终端并打开 Save Point。
- 服务卡片可打开本地网页；异常服务可触发既有端口释放流程。
- 刷新按钮能并行更新三类数据且有加载状态。
- 中英文词典键完全同步，现有前端测试、构建和 Rust 检查保持通过。
