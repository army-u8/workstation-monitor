# 智能工作站内核与七项联动能力设计

## 背景

VibeDesk 已具备系统监控、Git Radar、Save Point、端口与进程管理、缓存清理、AI Agent 探测、Obsidian、环境检查和自动更新等独立能力。当前主要缺口不是再增加一个孤立的扫描页面，而是把已有数据和动作连接起来，让应用能够解释事件、统一执行操作、形成自动化，并安全地扩展到菜单栏和局域网中的其他 Mac。

本设计覆盖七项新增能力：

1. 自动化规则中心。
2. AI Agent 指挥中心。
3. 全局命令面板。
4. 工作站事件时间线。
5. 智能健康诊断。
6. macOS 菜单栏。
7. 局域网多设备控制台。

## 目标与约束

### 目标

- 建立统一的事件、动作、权限和审计内核，让七项能力共享同一套行为语义。
- 将现有快照、端口、进程、清理和项目操作注册为可发现、可授权、可审计的动作。
- 形成“事件 → 诊断 → 自动化 → 确认 → 执行 → 审计”的闭环。
- 保持已有 REST API、WebSocket 消息和页面行为向后兼容。
- 在不依赖云服务的前提下支持局域网设备发现和安全配对。

### 已确认约束

- 继续交付单个 Rust 二进制，不要求用户安装 Node.js、数据库或其他运行时。
- 多设备能力仅支持局域网自动发现和验证码配对，不引入公网中继。
- 动作使用分级权限：安全动作可自动执行；杀进程、清理文件、重启服务等危险动作默认需要确认，用户可按规则或设备单独授权。
- 前端新增文案必须同时进入中英文词典，`.tsx` 中不得硬编码用户文案。
- UI 图标只使用 `frontend/src/components/Icons.tsx` 导出的 Tabler Icons。

## 方案选择

采用“统一事件与动作内核”，不把七项能力实现成相互独立的功能岛，也暂不建设动态插件系统。

统一内核由以下模块构成：

- **Event Hub**：归一化接收资源、进程、端口、Git、Agent、自动化和远端设备事件。
- **Action Registry**：注册动作元数据、参数、可用性、风险等级和执行器。
- **Rule Engine**：将事件、条件、动作、冷却和授权组合成自动化规则。
- **Policy Engine**：决定动作是否允许直接执行、需要用户确认或需要管理员权限。
- **Audit Log**：记录动作请求、确认、拒绝、执行结果、耗时和来源。
- **Peer Manager**：负责局域网发现、设备配对、权限、连接和撤销。

命令面板、菜单栏、REST API、自动化规则和远端设备都通过 Action Registry 执行动作，避免不同入口拥有不一致的权限和错误处理。

## 总体架构

```text
系统采集器 / Git / 端口 / AI Agent / 局域网设备
                       │
                       ▼
                  Event Hub
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   时间线持久化      Rule Engine      WebSocket
        │              │              │
        │              ▼              ▼
        └──────── Action Registry ── 前端工作台
                       │
                       ▼
                Policy + Audit
```

### 事件模型

`WorkstationEvent` 至少包含：

- `event_id`：全局唯一事件标识。
- `device_id`：事件所属设备。
- `event_type`、`source` 和 `severity`：稳定的机器可读分类。
- `occurred_at`：事件发生时间。
- `correlation_id`：将一次诊断和执行链路关联起来。
- `schema_version`：允许事件载荷向后兼容演进。
- `payload`：事件类型对应的结构化数据。

### 动作模型

`ActionDefinition` 描述动作标识、参数结构、风险等级、目标能力和当前可用性。`ActionRequest` 包含唯一 `request_id`、目标设备、参数、来源、请求者和确认凭据。`ActionResult` 记录状态、耗时、脱敏摘要、错误及可用的回滚引用。

相同 `request_id` 必须保证幂等，防止网络重试导致重复杀进程、重复清理或重复创建快照。

### 自动化模型

`AutomationRule` 包含：

- 触发事件和条件表达式。
- 一个或多个顺序动作。
- 冷却时间、超时和失败策略。
- 生效设备范围。
- 是否启用及授权状态。

规则自身产生的事件必须带来源链路，Rule Engine 用链路和执行锁阻止递归触发。

## 持久化设计

使用编译进二进制的 SQLite 保存：

- 事件时间线和聚合指标。
- 动作请求与审计结果。
- 自动化规则及授权。
- 已配对设备、公开身份和权限。
- 数据库版本与迁移记录。

高频 CPU、内存和网络样本先在内存中聚合，再按时间窗口写入。用户可配置保留天数和容量上限，超限后压缩或删除最旧数据。

设备私钥不写入 SQLite，而是存入 macOS Keychain。数据库不可写时，系统退化为有容量上限的内存时间线，既有监控和动作执行继续运行，并向前端发出持久化故障事件。

## 七项产品能力

### 1. 自动化规则中心

- 展示规则启停状态、最近触发、下一次可执行时间和结果。
- 使用可视化的“触发事件 → 条件 → 动作”编辑器，不要求用户编写脚本。
- 支持规则试运行，试运行只展示将要执行的动作和权限要求。
- 具备冷却、去重、执行锁、超时和有限重试。
- 安全动作可自动执行；危险动作需要确认或明确的单规则授权。

### 2. AI Agent 指挥中心

- 展示 Agent 类型、项目目录、运行时长、CPU、内存、子进程和推断状态。
- 支持打开项目、跳转终端、创建 Save Point 和停止异常 Agent。
- 不读取 Agent 对话内容或提示词；状态主要根据进程、子进程、资源和活动时间推断。
- Agent 异常事件可进入诊断、时间线和自动化规则。

### 3. 全局命令面板

- 任意前端页面按 `⌘K` 呼出。
- 模糊搜索所有已注册且当前可用的动作。
- 执行前显示目标、参数、风险等级和影响范围。
- 最近动作和常用动作仅影响排序，不绕过权限策略。

### 4. 工作站事件时间线

- 统一展示系统、Git、端口、Agent、自动化、动作和远端设备事件。
- 支持按设备、来源、严重级别、项目和时间范围筛选。
- 通过 `correlation_id` 展示一次问题从发现到解决的完整链路。
- 审计记录不可由普通清理动作删除，删除或导出必须经过专门权限。

### 5. 智能健康诊断

- 形成工作站健康分和按影响排序的问题列表。
- 首批检查 PATH 冲突、重复运行时、磁盘缓存、孤儿进程、端口冲突、密钥状态和服务异常。
- 每个问题提供证据、影响、建议动作和可撤销性说明。
- 修复动作统一通过 Action Registry，不在诊断组件中直接修改系统状态。

### 6. macOS 菜单栏

- 同一个可执行文件支持服务模式和菜单栏模式，不产生额外安装依赖。
- 展示健康摘要、Agent 数量、告警数量和连接状态。
- 提供打开工作台、运行诊断和执行已授权安全动作等快捷入口。
- 菜单栏模式通过受限的本机接口连接服务；菜单栏退出或崩溃不得影响后端。

### 7. 局域网设备控制台

- 自动发现同一局域网内的 VibeDesk 实例。
- 使用六位验证码确认双方设备指纹，配对后使用固定设备身份进行加密通信。
- 设备默认只读，可查看健康摘要、Agent 状态和告警。
- 远程危险动作默认必须在目标 Mac 上确认；可按“设备 + 动作”明确授权。
- 撤销配对后立即废除访问权限，离线请求不会无限排队。

## 信息架构

新增三个主要入口：

- **控制中心**：自动化规则、可用动作、当前告警和最近执行。
- **活动**：事件时间线和审计记录。
- **设备**：本机和已配对的局域网 Mac。

Agent 指挥和健康诊断继续融入现有工作台，并可从控制中心进入详情。命令面板和菜单栏作为全局入口，不额外占用侧边栏位置。

## 安全与故障处理

- 局域网发现只广播设备名称、版本和临时配对标识，不广播遥测数据。
- 所有远端请求经过设备身份校验、权限检查和审计。
- 敏感值在写入事件和审计记录前脱敏。
- 只有无副作用或具备严格幂等保证的动作可以自动重试。
- 危险动作失败后不盲目重试；错误结果进入时间线并允许用户再次手动发起。
- 远端设备断线时快速失败并记录最终状态，不无限积压动作。
- 菜单栏和远端连接异常不得阻塞本机采集、WebSocket 广播和既有 API。

## 兼容性

- 保留现有 REST 路径和响应字段。
- 保留现有 WebSocket 消息；新事件使用独立消息类型，旧前端可安全忽略。
- 现有 store 方法逐步改为调用统一动作接口，但保留旧调用入口直到回归验证完成。
- 所有持久化结构通过显式迁移升级，不假设数据库永远从空状态创建。

## 分期交付

### 里程碑一：本机控制内核

- Event Hub、Action Registry、Policy、Audit 和 SQLite。
- 工作站时间线与全局命令面板。
- 将现有快照、端口、进程、清理等操作接入动作系统。

验收重点：不同入口执行结果一致、执行链路可追踪、旧 API 不回归、数据库故障可降级。

### 里程碑二：智能联动

- 自动化规则中心。
- Agent 指挥中心。
- 智能健康诊断。

验收重点：规则可创建和试运行、危险动作不可越权、Agent 异常形成处理闭环、规则不会递归触发。

### 里程碑三：macOS 菜单栏

- 菜单栏摘要、告警、通知和安全快捷动作。
- 后端断线重连与进程隔离。

验收重点：菜单栏故障不拖垮服务、后端重启后恢复连接、权限不可绕过。

### 里程碑四：局域网设备

- 发现、配对、身份、权限、远端摘要和动作请求。
- 撤销、离线和远端审计。

验收重点：未配对设备不可读取数据、默认只读、目标设备确认危险动作、网络重试不产生重复执行。

## 测试与质量门禁

- Rust 单元测试覆盖事件归一化、动作幂等、权限判定、规则匹配、冷却和循环阻断。
- 集成测试覆盖“事件 → 规则 → 权限 → 动作 → 审计”完整链路。
- 数据库测试覆盖迁移、并发写入、容量清理、损坏和只读降级。
- 前端测试覆盖命令搜索、权限确认、规则编辑、时间线筛选和空状态。
- 多设备测试使用两个本地实例验证发现替代层、配对、撤销、离线和重复请求。
- 每个里程碑运行 `bun --cwd frontend run lint`、`bun --cwd frontend run i18n:check`、`bun --cwd frontend run build`、`cargo test --offline` 和 release build。

## 非目标

- 不提供云端账号、互联网中继或公网远程控制。
- 不读取 AI Agent 的对话内容。
- 不在首期开放任意第三方动态插件加载。
- 不允许自动化规则绕过系统权限或 VibeDesk 的风险确认。
